# pi-factory 1.1.0

*"The codebase is the fuel; agents can't damage it; the machinery stays agnostic."*

The code base is what the team uses to bring value to customers. v1.1.0 makes sure every mission leaves it **safe, understandable by any human, battle-tested and predictable**, and that agents with bash can't do harm on the way. Each entry names the issue and the fix.

## Code health gate (G5)

| Issue | Fix |
|---|---|
| Per-ticket reviews see small diffs; erosion across a mission (duplication, clever abstractions, untested failure paths) had no owner | **Code steward** (`factory-code-steward`, fresh, family ≠ workers) judges the whole mission diff against a written, repo-owned **quality bar** (`docs/agents/quality-bar.md`, `QB-` items), with evidence per item (D49) |
| "Clarity over cleverness" was an opinion | The steward explains every changed source file in three sentences; **the gate fails on a file it couldn't explain** (D49) |
| Nothing measured health, so nothing stopped it degrading | **Ratchet** (`health.sh`): duplication, large files, deep nesting, debt markers, skipped tests, plus your repo tool (`FACTORY_HEALTH_CMD`). May improve, never worsen `.factory/health-baseline.json` (D50) |

## Agents that can't do harm

| Issue | Fix |
|---|---|
| Workers and the lead have bash on your laptop, with your identity | **Command guard** (`.pi/extensions/factory-guard.ts`): blocks push, force, `--no-verify`, history rewrites, `sudo`, recursive deletes of `/ ~ .. .git`, cluster/cloud/secret-store changes, uploads, remote shells, credential and `.env` reads, publishing, merging, writes to the factory, CI or hooks (D51) |
| The wall around the instrument was soft (git history) | The guard blocks routes to `instrument/` from a worker worktree |
| A worker could weaken checks to get green: skip a test, delete one, silence a linter, touch CI | **Patch guard** at integration: such patches never land, and the block is a recorded round. The fix lane applies the same rules to human changes (except paths) (D51) |

## Less manual work

| Issue | Fix |
|---|---|
| Tickets written by hand, then fixed by hand (missing ticket, missing `## Covers`) | **Ticket writer** drafts tickets and fix tickets from findings; you approve in one word: `/factory-approve <f> tickets` (D52) |
| The core ticket failed twice on the efficient worker | `**Size:** L` tickets go straight to the heavy worker (D52) |
| After fix tickets were built, the mission asked for fix tickets again | A failing behavior verdict is re-validated once fixes are built (D53) |

## Agnostic machinery, owned content

The factory builds and maintains whatever you work on: a bot, an API, a front end, a batch job, in any language. This release keeps that true while letting it learn a kind of software, without adding a single role or script.

| Issue | Fix |
|---|---|
| The only domain knowledge was a conversational-bot checklist, used even for a batch bot (mission 1 retro #8) | **Practice packs**: `packs/<name>/` holds a contract checklist (read by the author and critic at G1) and `QB-<PACK>-NN` items (read by the steward at G5). `install-into.sh <repo> --pack <name>`, repo-owned once copied (D54) |
| A blank-page API had no conventions to start from | **`api` pack**, Stripe-inspired: one error shape, idempotency keys, cursor pagination, request IDs, additive changes, money and time types; **Public** items (versioning, signed webhooks, expansion) only for third-party APIs |
| Batch jobs need their own questions (exit codes, safe re-runs, partial failure) | **`batch` pack**, built from mission 1's decisions. Packs are shapes, not labels: a batch bot is `batch`. The old conversational-bot checklist was too thin to keep (no quality bar, no answer for non-deterministic behavior); an `llm-app` pack will be written from the first mission that needs it |
| No licence: "all rights reserved" by default | **MIT** (`LICENSE`); the vendored skills keep their own MIT notice |

## Upgrade notes

- Run `install-into.sh` again on each target repo (its own MR). It adds the two agents, the guard, the quality bar (yours to sharpen) and **today's health baseline**.
- Set `model:` for `factory-code-steward` (a family different from the workers) and `factory-ticket-writer`; `models-lint` checks it.
- In Pi, trust the project so the guard loads. Working on pi-factory itself: `FACTORY_GUARD=off pi`.
- `docs/agents/contract-checklist-bots.md` is no longer installed by default. A repo that already has it keeps it (it is repo-owned). A batch bot takes `--pack batch`; remove the old file in the install MR.
- Briefs now read every `docs/agents/contract-checklist-*.md` and `docs/agents/quality-bar-*.md` present.
- A mission already in flight before 1.1.0 can skip G5 with `FACTORY_G5=off` on the gate; new missions can't.

## Considered, not adopted

**Pi Durable** (Earendil, experimental): a framework for durable agent applications. Not now: the factory's durability comes from files and git, and a TypeScript runner would be a second architecture on an unstable API. Candidate for the Step 3 runner after Step 2 (roadmap X13).

## Verified

- End-to-end mission test: 71 checks (ticket writer, size routing, packs, patch guard, ratchet failing and recovering, steward gate rejecting an unexplained file, G1–G5).
- Guard unit tests: 4 suites, dangerous commands blocked and normal development allowed.
- Not verifiable without a live Pi: whether pi-subagents children load project extensions. The patch guard holds either way; confirm on mission 2 (`.pi-subagents/guard.log`).
