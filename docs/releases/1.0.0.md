# pi-factory 1.0.0

*"It held up in production; now it can't lie and doesn't stall."*

Every change below comes from mission 1 (a batch bot feature that deletes production data, run end to end through the factory, MR merged). Each entry names the issue we hit and the fix.

## Breaking changes

- **CI jobs moved** from `.gitlab-ci.yml` to `templates/gitlab/factory.gitlab-ci.yml`. In a target repo: `include: [{ local: .factory/ci/factory.gitlab-ci.yml }]` (installed by `install-into.sh`).
- **Verdicts must be recorded by `collect.sh`.** The gate rejects verdicts without history or edited after recording. For a mission started before 1.0: `scripts/factory/collect.sh <feature>`.
- **No integration without tests.** `FACTORY_TEST_CMD` must be set in `.factory/commands.env` (escape hatch for a toy repo: `FACTORY_ALLOW_NO_TESTS=1`).

## Records that can't overstate

| Issue in mission 1 | Fix |
|---|---|
| A ticket showed "round 1" after two failed runs and an escalation; metrics claimed 100% first-pass | Rounds come from verdict history (`<stem>.rN.md`), numbered by `collect.sh`; first-pass reads round 1 (D38) |
| A worker run ending without a patch didn't count, so escalation needed a hand-written verdict | `record-no-patch.sh`: a missing patch is a recorded failed round; round 2 goes to the heavy worker (D38) |
| Every verdict named a model that wasn't in use | `collect.sh` writes the model configured for the role (D39) |
| The lead searched temp folders for each worker's patch | The build wave returns `patch`; `locate-patch.sh` falls back (D39) |
| All behavior assertions "passed" with no harness | Evidence or label: `PASS — evidence`, `FAIL`, `UNVERIFIED — why`. G4 blocks unverified behavior until proven or accepted by a human (D40) |

## Humans decide in one word, and never watch

| Issue | Fix |
|---|---|
| Approval typed into `spec.md` by hand; decisions only in chat | `/factory-approve`, `/factory-decide`, `/factory-amend`, `/factory-accept-unverified`, all logged in `decisions.tsv`, which every role reads (D43) |
| A worker proceeded on a timed-out question, against the spec | Irreversible choices (deletes, secrets, production behavior, the contract) never default: `DECISION NEEDED` → `STEP: decide` (D47) |
| Long waves watched on screen | Notification on every human step (D45) |
| VPN drop, lead loop, full context: restarts from memory | `/factory-pause` and resume from files; auto-pause above ~70% context; watchdog rule (D45) |
| 7 connection errors when the VPN dropped | Pre-flight `doctor.sh --quick` before every run, with a gateway check (D46) |
| `checkpoint.sh` run by hand about ten times | Scripts commit mission state themselves (D46) |

## Small changes stop costing a mission

| Issue | Fix |
|---|---|
| A three-line chart fix went outside any gate | `/factory-fix`: blast radius, checks, one fresh reviewer; checked by the MR gate (D41) |
| Chart lint only failed in CI | `FACTORY_EXTRA_CMD` runs in integration and the fix lane (D44) |
| A docs or values tweak invalidated the behavior verdict | Behavior staleness scoped to `.factory/behavior-paths` (D42) |
| The feature MR carried 193 files of tooling | `install-into.sh` commits on its own branch for its own MR (D48) |
| The gate only ran on the laptop | Includable CI template (C11) |
| Two waves in the same second overwrote a workflow file | Unique workflow file names |
