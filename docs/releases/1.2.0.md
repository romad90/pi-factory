# pi-factory 1.2.0

*"Agnostic machinery, owned content."*

The factory builds and maintains whatever you work on: a bot, an API, a front end, a batch job, in any language. This release keeps that true while letting it learn a kind of software, without adding a single role or script.

| Issue | Fix |
|---|---|
| The only domain knowledge was a conversational-bot checklist, used even for a batch bot (mission 1 retro #8) | **Practice packs**: `packs/<name>/` holds a contract checklist (read by the author and critic at G1) and `QB-<PACK>-NN` items (read by the steward at G5). `install-into.sh <repo> --pack <name>`, repo-owned once copied (D54) |
| A blank-page API had no conventions to start from | **`api` pack**, Stripe-inspired: one error shape, idempotency keys, cursor pagination, request IDs, additive changes, money and time types; **Public** items (versioning, signed webhooks, expansion) only for third-party APIs |
| Batch jobs need their own questions (exit codes, safe re-runs, partial failure) | **`batch` pack**, built from mission 1's decisions; the bot checklist moved to the **`bot` pack** |
| No licence: "all rights reserved" by default | **MIT** (`LICENSE`); the vendored skills keep their own MIT notice |

## Upgrade notes

- `docs/agents/contract-checklist-bots.md` is no longer installed by default. A repo that already has it keeps it (it is repo-owned). New bot repos: `--pack bot`.
- Briefs now read every `docs/agents/contract-checklist-*.md` and `docs/agents/quality-bar-*.md` present.

## Considered, not adopted

**Pi Durable** (Earendil, experimental): a framework for durable agent applications. Not now: the factory's durability comes from files and git, and a TypeScript runner would be a second architecture on an unstable API. Candidate for the Step 3 runner after Step 2 (roadmap X13).
